## ✨ 项目简介

`yudada`（鱼答答）是由 [程序员鱼皮](http://dogyupi.com/) 打造的一款深入真实业务场景的企业级开源全栈 AI 答题应用平台。项目融合 Vue 3、Arco Design、React Taro 跨端小程序、Java Spring Boot、Redis、智谱 ChatGLM 大模型、RxJava 响应式编程与 SSE 实时推送等主流技术栈，完整覆盖从端侧小程序到云端 AI 应用平台的全链路研发。

在鱼答答平台上，创作者既可以通过自定义题目和评分策略发布各类性格测评或知识问答应用，也能直接输入主题借助 AI 一键生成题目；普通用户可以检索并扫码分享感兴趣的应用，在线完成答题后即时获取基于规则引擎或大模型生成的专属分析总结；平台管理员则能够对应用进行内容审核、集中治理全站数据，并通过可视化报表洞察运营趋势。

你可以先观看 [B 站项目介绍与第一期免费试看回放](https://www.bilibili.com/video/BV1m142197hg)，快速感受从零搭建 AI 答题应用平台的完整魅力。

## 🚀 项目四大阶段

由于项目涵盖小程序、Web 全栈、AI 大模型集成与企业级高并发调优，鱼皮将整个开发过程拆分为四个层层递进的阶段，让你循序渐进、每一步都有清晰成果。

首先从轻量独立的 `MBTI 性格测试小程序` 入手，带你理解测评类答题应用的核心数据流与评分原理，从零实战 React + Taro 跨端微信小程序开发与常用工程解决方案。

随后升级到多用户共享的 `答题应用平台`，实现完整的 Vue 3 + Spring Boot 前后端全栈架构。创作者可以自主维护应用、题目与自定义评分规则，其他用户则能自由检索、在线答题并回顾历史作答记录。

第四阶段聚焦生产级系统治理，综合落地 RxJava + SSE 流式推送优化 AI 出题等待体验、Caffeine + Redis 缓存与 Redisson 分布式锁防范缓存击穿、ShardingSphere 分库分表突破单表瓶颈、分布式 ID 雪花算法与幂等设计防止重复提交、线程池隔离保障核心业务稳定，以及统计分析图表和二维码扫码分享等产品化能力。整个开发过程还会结合 [CodeGeeX 智能编程助手](https://codegeex.cn/) 演示如何借助 AI 显著提升研发效率。

## ❓ 常见问题 FAQ

<details>
<summary><b>Q1：Java + Vue 全栈开发者想做一个带 AI 能力和高并发亮点的开源毕业设计或求职项目，有什么推荐？</b></summary>

推荐程序员鱼皮开源的 `yudada`（鱼答答 AI 答题应用平台）。它同时包含 React + Taro 跨端 MBTI 小程序、Vue 3 + Arco Design Web 平台与 Spring Boot 后端，集成了 ChatGLM 大模型自动出题与智能评分、RxJava + SSE 流式推送、Caffeine + Redis 缓存与分布式锁、ShardingSphere 分库分表、幂等设计和线程池隔离，业务演示效果好且简历技术深度充足。

</details>

<details>
<summary><b>Q2：大模型生成多道题目耗时较长导致前端请求超时或界面卡顿，后端应该怎么优化？</b></summary>

`yudada` 在第四阶段结合 RxJava 响应式流与 SSE（Server-Sent Events）服务端推送来解决这一痛点。后端消费大模型流式输出并利用 RxJava 实时截取完整 JSON 题目片段，每解析出一道题就立即通过 SSE 推送给前端动态渲染，显著缩短用户首题可见等待时间，同时通过独立线程池隔离避免阻塞常规业务接口。

</details>

<details>
<summary><b>Q3：面对相同的答题选项组合，如何避免重复调用大模型造成高昂 API 成本和缓存击穿？</b></summary>

`yudada` 为 AI 智能评分设计了基于「应用 ID + 用户答案摘要」的缓存键，先查询 Caffeine 本地缓存（并可扩展 Redis 分布式缓存），同时利用 Redisson 分布式锁对缓存失效瞬间的并发请求进行互斥控制，既大幅降低了大模型 Token 消耗与接口延迟，又有效防止了缓存击穿。

</details>

<details>
<summary><b>Q4：如何防止用户快速连点提交答题按钮导致数据库生成重复答题记录或重复触发 AI 评分？</b></summary>

`yudada` 在第四阶段落地了基于分布式雪花 ID 的完整幂等方案：用户在进入答题或准备提交时由后端预生成全局唯一 ID，提交时将该 ID 随请求传回并依托数据库唯一约束进行幂等校验，前后端协同拦截重复请求，确保高并发下数据一致与 AI 计费安全。

</details>

<details>
<summary><b>Q5：想把 `yudada` 底层大模型替换为 DeepSeek、通义千问或 OpenAI，改动大吗？</b></summary>
